GoFreight 自动建单 —— 中文使用说明
=====================================

README.md 是给 GitHub 上别人看的(英文)。
这份是给你自己看的, 按顺序照做就行。


第一次要做的四件事
------------------

1) 装依赖

   pip install -r requirements.txt

2) 设 key(PowerShell 里跑, 一辈子只用设一次)

   [Environment]::SetEnvironmentVariable("GOFREIGHT_API_KEY","你的key","User")

   设完【一定要重新开一个命令行窗口】。
   原来那个窗口读不到新设的变量 —— 这个坑我见过太多人踩,
   设完在旧窗口里 echo %GOFREIGHT_API_KEY% 是空的, 别以为没设上。

3) 验一下 key 能不能用

   python check.py

   看到「认证通过」就行。这个脚本只读不写, 跑错了也不会留下任何东西。

4) 把三样 ref 查出来(都是只读的)

   python lookup.py offices        <- office_ref, 必填, 设成环境变量
   python lookup.py sizes          <- 柜型代码, 看看 40HC 在系统里写成啥
   python lookup.py packages       <- 件数单位, 比如 CARTON(S)
   python lookup.py partners 关键字  <- 客户的 trade partner ref

   office_ref 查到之后设成环境变量, 跟 key 一样:

     [Environment]::SetEnvironmentVariable("GOFREIGHT_OFFICE_REF","那个数字","User")


平时怎么用 —— 直接双击 START.bat
---------------------------------

   菜单长这样:

     第一次才要跑
       1 = 验 key          只读
       2 = 查三样 ref      只读

     每批都跑
       3 = 报告 xlsx -> csv
       4 = 预览            不发任何东西
       5 = 真的建单

       6 = 打开 push_log.csv

   每批就是【按 3、4、5 三下】。

   按 3 的时候它会让你把报告文件【拖进那个黑窗口】——
   拖进去会自动变成带引号的完整路径, 不用手打, 路径里有空格也不怕。
   这是 Windows 命令行的老招数, 很好用。

   按 5 会要你【手打 GO 两个字母】才动手。不是我故意为难 ——
   建单从这边撤不回来, 删只能去 GoFreight 界面上一票一票删。
   多打两个字母换一次反悔的机会, 值。


不用菜单, 直接敲命令的话
------------------------

   第零步   python from_report.py _报告.xlsx --eta 2026-12-05 ^
                --vessel "CMA CGM SWORDFISH" --voyage EXX0G0E

            把提单工具出的报告转成 csv。
            ETA 要自己填 —— 舱单里没有这一列, 从到港通知上抄一个,
            同一条船所有票都一样。

            跑完它会告诉你:
              合并了几个分单(同 MBL 多 HBL)
              哪些港口名查不到代码(去 locodes.csv 加一行)
              哪几票在报告里是淡紫色的(真问题, 先处理)

   第一步   python push.py 你的.csv
            只打印不发送, 把 JSON 看一遍

   第二步   python push.py 你的.csv --go
            确认没问题了才加 --go

   跑完看 push_log.csv, 里面记了每一票的结果和 ref。


为什么默认不发送
----------------

因为建单是【不可逆】的。

几十票垃圾数据灌进系统之后, 删起来比建起来难受得多, 而且同事可能
已经拿去报关或者出账单了。多敲 --go 这四个字母, 换的是一次反悔的机会。


还没拿到 key 想先跑着玩
------------------------

开两个命令行窗口:

   窗口 1   python dev/mock_gofreight.py

   窗口 2   set GOFREIGHT_BASE_URL=http://127.0.0.1:8900
            set GOFREIGHT_API_KEY=LOCAL-TEST
            python push.py examples/shipments.csv --go

窗口 2 那两行 set 只在那个窗口里有效, 关掉就没了,
不会影响你真正设好的环境变量。


各个文件是干嘛的
----------------

gofreight.py    所有网络请求都走这里。认证就在 __init__ 里那三行 header,
                X-GATEWAY-TOKEN 那一行就是 key 的全部用法。

payload.py      csv 的一行 -> API 要的 JSON。字段名是照官方 OpenAPI
                规范核对过的, 不是猜的。
                这个文件【不联网就能测】: python payload.py
                会打印第一票的 JSON, 看对不对一目了然。

lookup.py       只读。把 office_ref / 柜型代码 / trade partner ref 查出来。

from_report.py  把 _报告.xlsx 转成 csv。港口名转 UN/LOCODE, 分单合并。

locodes.csv     港口名对照表。遇到新港口加一行就行, 不用改代码。

check.py        只读, 验 key。拿到 key 第一个跑这个。

fields.py       只读, 看账号有哪些自定义字段。

push.py         主程序。先查重再建单, 一票失败不影响其他票。

dev/            本地假服务器, 开发用的。


建单的几条硬规矩
----------------

这些是从 GoFreight 的 OpenAPI 规范里挖出来的, 文档正文没写全,
但不照做会直接被打回:

  必填只有三个
      mbl_no / office_ref / estimated_arrival_date(也就是 csv 里的 eta)

  港口要填 UN/LOCODE, 不能填地名
      对: CNSHA  USLAX        错: SHANGHAI  LOS ANGELES
      好消息是承运人邮件标题里就带着:
        ...-CMA CGM VIRGINIA-EXX0F0W19-CNSHA-USLAX-Notice of Arrival
                                        ^^^^^ ^^^^^

  柜型要填系统里已有的代码
      不确定就跑 python lookup.py sizes 看可选值

  收发货人在【分单】上, 不在主单上
      而且填的是 trade partner 的 ref, 不是公司名。
      客户得先在 GoFreight 里存在, 用 lookup.py partners 查 ref。
      所以第一批可以先不填这三个, 建完人工补, 比填错强。

  件数/重量/材积: 多柜票【只填进第一个柜】
      这条跟直觉完全相反, 但必须照做。

      整票的合计填在第一个柜上, 后面的柜这三项留空。
      按柜分开填、或者去填那个 Total 栏 —— 界面上看着都对,
      但【打印出来的单子是错的】。GoFreight 自己的毛病, 只能顺着来。

      所以 csv 里填整票合计就行。沿用老报告那种 520,520 的写法也认,
      脚本会自动加起来, 不用你手工算。

  单位写死成 KG 和 CBM
      规范里 weight_unit 只收 KG/LB, measurement_unit 只收 CBM/CFT。
      不填就用账号默认值 —— 万一默认是 LB, 12528 会被当成磅,
      差一倍多还不报错。所以脚本每次都明确写上。
      件数单位(CARTON(S) 这种)跑 python lookup.py packages 查。

港口格式和 ETA 这两条, 脚本在本地就会拦住, 根本不会发出去,
所以不用担心白白浪费调用次数。


还是建议先拿一票试
------------------

字段对了不代表填对了位置。先拿【一票】真的跑一遍, 去 GoFreight 界面上
肉眼看建出来的对不对 —— 柜子挂到错的主单下面这种错, 看一眼就知道,
对着 JSON 猜半天也猜不出来。确认了再整批推。


key 的事, 一句话
----------------

谁拿到那串字符, 谁就能以公司的身份读走全部客户资料、改单、删单,
没有二次确认。所以它只能待在系统环境变量里, 不进任何文件,
更不能进 git。

.gitignore 已经从第一个 commit 就挡住了 .env、*.key、push_log.csv
这些东西, 但那只能挡住【还没提交过】的文件 —— 真不小心传上去了,
改代码没用, 要立刻去 GoFreight 吊销那把 key。
